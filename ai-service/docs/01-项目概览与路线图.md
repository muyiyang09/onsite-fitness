## 1. 当前功能现状

### 1.1 服务边界

| 项 | 值 |
|---|---|
| 服务名 | `onsite-fitness-ai` |
| 角色 | Spring Boot 主后端旁挂的独立 AI 微服务，**只读** onsite_fitness 库 |
| 端口 | `18000`（MCP 预留 `18001`） |
| HTTP 框架 | FastAPI 0.115.6 + Uvicorn 0.32.1 |
| 部署形态 | Dockerfile 多副本（`--workers 2`）+ docker-compose 编排，已进主编排 |
| Agent 框架 | LangGraph 1.1.4（StateGraph + Checkpointer + interrupt） |
| LLM 路由 | LiteLLM 1.55.3（DeepSeek / Qwen / OpenAI） |
| 向量库 | Milvus（生产唯一；pymilvus 可选重依赖，未装时降级 BM25 单路） |

**对外接口清单：**

| Method | Path | 说明 |
|---|---|---|
| GET | `/healthz` | Liveness：进程存活（不查依赖） |
| GET | `/readyz` | Readiness：DB / Redis / LLM 探活 |
| GET | `/metrics` | Prometheus 指标导出 |
| POST | `/v1/ai/recommend-coach` | 教练智能推荐（Agent 1） |
| POST | `/v1/ai/feedback` | 用户反馈回流（在线 Eval 集） |
| POST | `/v1/ai/review-summary` | 评价摘要（Agent 2） |
| POST | `/v1/ai/cert-review` | 证书审核（Agent 3，HITL 开启时返回 pending） |
| POST | `/v1/ai/cert-review/{thread_id}/resume` | HITL 人工确认（approve / reject） |
| POST | `/v1/ai/cert-review/{thread_id}/cancel` | HITL 取消审核单 |
| POST | `/v1/ai/chat` | 统一入口（Supervisor 路由） |

### 1.2 三个 Agent + 一个路由

| Agent | 图文件 | 职责 | 关键能力 |
|---|---|---|---|
| `recommend_coach` | [graphs/recommend_coach.py](../app/graphs/recommend_coach.py) | 自然语言 → Top N 教练 + 理由 | 3 节点 DAG（意图抽取 → 混合检索 + 5 维打分 → 理由生成）；BM25+Milvus 混合召回 |
| `review_summary` | [graphs/review_summary.py](../app/graphs/review_summary.py) | 批量评价 → 优缺点 + 标签 | 多评价 reduce 摘要 |
| `cert_review` | [graphs/cert_review.py](../app/graphs/cert_review.py) | 证书 OCR → 核验 → 风险评估 | 工具循环 + HITL `interrupt` + 管理员 resume |
| `supervisor` | [graphs/supervisor.py](../app/graphs/supervisor.py) | `/v1/ai/chat` 统一路由 | LLM 判定意图 → 派发对应 Agent（默认关，可直连子 Agent） |

**推荐 Agent 拓扑（3 节点，Node2 空结果走 conditional 回退）：**

```
START → Node1 意图抽取(LLM) → Node2 检索+打分(规则+混合检索) → Node3 理由生成(LLM) → END
                                    └── 空候选 → 回 Node1 放宽条件重抽（Loop）
```

### 1.5 轻量降级设计（关键架构决策）

向量/重排重模型（bge-m3 / bge-reranker，GB 级）在国内难下载，故采用**逐级降级**策略，任何一路缺失都不抛异常打断主链路：

```
3 路（BM25 + 向量 + 重排）→ 2 路（BM25 + 向量）→ 1 路（BM25 单路 min-max 归一化）→ 0 路（退回 #03 子串匹配）
```

- Milvus 不可达 / pymilvus 未装 → 向量召回返回空，自动走 BM25 单路。
- Embedding 模型未装 → `embed()` 返回空数组，`upsert_coaches` 返回 0，不阻塞启动。
- 重排依赖缺失 → no-op 原样返回。
- 所有「保护组件」（Redis 限流/预算）故障 → fail-open，放过流量而非全拦。

## 2. 商业化落地对比（从差距到现状）

> 原 v1.0 本文档列出的商业化差距，现逐项标注落地状态。**已全部消除或降级为「可选重依赖」**。

| 维度 | 原差距 | 现状 |
|---|---|---|
| API 入口同步阻塞 | 同步 `def` 阻塞 event loop | ✅ 全链路 async + `ainvoke` + `acompletion` |
| MySQL 连接池默认 5 | 峰值并发打满 | ✅ `pool_size=20` + `max_overflow=10` + `pool_pre_ping` |
| Redis 缓存未用 | 相同 query 每次打 LLM | ✅ 24h 结果缓存 + cache_key |
| 无限流 | 恶意刷 | ✅ 三级限流（全局/IP/用户）+ Token 预算 |
| 无熔断 | LLM 连续失败拖垮 | ✅ LLM 熔断器（半开试探） |
| 部署形态单实例 | 无容器化 | ✅ Dockerfile + 多副本 + compose 编排 |
| 健康探针浅 | 不查依赖 | ✅ `/healthz`(liveness) 与 `/readyz`(readiness) 分离 |
| 无优雅停机 | SIGTERM 丢请求 | ✅ lifespan + `--timeout-graceful-shutdown` |
| 无监控 | 看不见瓶颈 | ✅ `/metrics` + 结构化日志 + request_id |
| 目录分层混乱 | main.py 混编排 | ✅ clients/graphs/middleware/core/eval/mcp/tools 分层 |
| 错误码缺失 | 通用 500 | ✅ 错误码 + 全局异常中间件 + 不泄露栈 |
| 测试覆盖不足 | 1 个 smoke test | ✅ 10 个测试模块（hybrid/hardening/loop/eval/tools/checkpoint/safety/metrics/agents/recommend） |
| API 无版本 | 破坏性变更无退路 | ✅ `/v1/` 前缀 |

## 3. 剩余路线图（重排后）

已落地 Phase 1–5（Loop / 加固 / Harness / MCP / 多 Agent），剩余项按「ROI + 依赖」重排：

### 🟠 P0 · 向量路真跑起来（依赖环境，非代码缺口）
- **装重依赖**：`cd ai-service && pip install -e ".[vector-milvus]"`（pymilvus）+ bge-m3 embedding 模型。
- **起 Milvus**：`docker-compose up -d milvus`（已进主编排，含 etcd + minio + milvus + attu）。
- **验收**：`POST /v1/ai/recommend-coach` 日志出现 `[VectorStore] 召回 N 条`；`upsert_coaches` 返回 >0。
- 代码侧已就绪，缺的只是**有 GPU / 可访问 HuggingFace 的部署环境**。

### 🟡 P1 · 在线 Eval 回流闭环
- `feedback` 端点已把用户点赞/点踩/下单写入 `ai_eval_online` 表（在线 ground truth 集）。
- 待补：定时任务把在线反馈回流成 Eval 集 → 触发离线 metric 回归 → 依据结果调 prompt/阈值。

### 🟡 P2 · Cross-Encoder 精排上线
- `reranker.py` + 配置开关 `RERANKER_ENABLED` 已就绪，默认关。
- 上线前提：下载 bge-reranker-v2-m3 重模型，改 `.env` 打开开关。

### 🟢 P3 · 可选增强
- MCP 工具层默认关（单进程直连够用），需跨语言/外部 LLM 共享工具时再开 `MCP_ENABLED`。
- Supervisor 统一入口默认关，直接调子 Agent 更省一层 LLM 路由。
