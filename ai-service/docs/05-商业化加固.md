## 1. 现状回顾

### 1.1 当前同步链路问题

```python
# app/main.py 当前
def recommend_coach(payload: RecommendCoachIn) -> RecommendResult:
    # ↑ 同步函数，每个请求占用 worker 线程池一个线程
    state_out = RECOMMEND_GRAPH.invoke(state_in)  # ← 同步 invoke
```

**问题**：FastAPI 是 ASGI 异步框架，但用 `def` 定义的端点会被丢到线程池执行。线程池默认 40 个线程，第 41 个并发请求会排队等。LLM 调用 60s 超时，40 个并发能阻塞所有线程，服务假死。

### 1.2 高可用缺口清单

| 项 | 现状 | 期望 |
|---|---|---|
| 部署 | `python -m app.main` | Docker + K8s 多副本 |
| 健康探针 | `/healthz` 浅探活 | `/healthz` (liveness) + `/readyz` (readiness 含 DB/LLM/Redis 探活) |
| 优雅停机 | 无 | SIGTERM → 拒新请求 → 等在飞 → 退出 |
| 熔断降级 | 节点级 fallback mock | 全局熔断器（连续 N 次失败 → 短路 → 走 mock） |
| 限流 | 无 | 每用户/IP/全局三级限流 |
| Token 预算 | 无 | 单用户单日上限 + 全局日上限 |
| 审计日志 | 无 | 所有 LLM/Tool 调用入 `ai_audit_log` 表 |
| 监控 | 无 | Prometheus metrics + Grafana |

## 2. 设计思路

### 2.1 异步化为什么是商业化的第一步

| 同步模型 | 异步模型 |
|---|---|
| 1000 并发需要 1000 线程 | 1 进程 1 事件循环扛 10000 并发 |
| 线程切换开销大 | 协程切换纳秒级 |
| 阻塞调用 = 服务假死 | I/O 等待时让出 CPU 给其他请求 |
| LiteLLM 调用占满线程池 | acompletion 立即让出 |

**关键认知**：LLM 调用本质是 I/O 密集型（等远程 API 返回），不是 CPU 密集型。I/O 密集型场景异步收益最大。

### 2.2 限流 vs 熔断 vs 降级

三个概念常被混淆：

| 机制 | 触发条件 | 目的 | 实现位置 |
|---|---|---|---|
| **限流** | QPS 超阈值 | 保护下游 | 入口（middleware） |
| **熔断** | 错误率超阈值 | 快速失败，避免雪崩 | 调用方（client 包装） |
| **降级** | 主链路失败 | 返回兜底结果 | 业务节点 |
| **重试** | 偶发失败 | 自动恢复 | client 包装（含退避） |

顺序：**限流在前 → 熔断在中 → 降级在后**。限流挡住恶意流量，熔断快速失败不传染，降级保证用户拿到结果（哪怕是 mock）。

### 2.3 Token Budget 为什么必须

LLM 成本是变量，恶意用户/被劫持账号能瞬间烧光预算。

| 维度 | 阈值 | 触发动作 |
|---|---|---|
| 单用户单次请求 | 10K token | 拒绝（防长 prompt 攻击） |
| 单用户单日 | 100K token | 拒绝并告警 |
| 全局单日 | 1M token | 告警，开启 mock 模式 |
| 全局单月 | 30M token | 告警，联系商务 |

### 2.4 为什么 API 加版本前缀

```
当前：POST /ai/recommend-coach
改后：POST /v1/ai/recommend-coach
```

破坏性变更（schema 字段调整/语义变化）必须走 `/v2`，老版本保留至少 6 个月。商业项目客户最怕"接口突然变了"。

```python
# app/clients/llm.py 已有 achat，但要包装 async chat_structured
async def achat_structured_with_retry(
    messages: Iterable[dict[str, str]],
    output_schema: Type[T],
    max_retries: int = 2,
) -> tuple[T, list[dict]]:
    all_messages = list(messages)
    last_exc = None
    for attempt in range(max_retries + 1):
        try:
            # 用 acompletion 而非 completion
            return await _achat_structured_async(all_messages, output_schema), all_messages
        except (RuntimeError, ValidationError) as exc:
            last_exc = exc
            if attempt == max_retries:
                break
            all_messages = all_messages + [{"role": "user", "content": f"...{exc}..."}]
    raise last_exc


async def _achat_structured_async(messages, schema):
    """async 版本的 chat_structured，用 acompletion"""
    schema_json = schema.model_json_schema()
    system_with_schema = "..."
    msgs = [{"role": "system", "content": system_with_schema}, *list(messages)]
    raw_text = await achat(msgs)
    parsed = json.loads(raw_text)
    data = normalize_for_pydantic(parsed, schema)
    return schema.model_validate(data)
```

```python
# app/clients/cache.py（新增）
"""Redis 缓存：高频相同 query 缓存 24h，节省 LLM 调用"""

import json
import hashlib
import redis.asyncio as redis
from app.config import settings

_pool = redis.ConnectionPool.from_url(settings.redis_url)


async def get_cache(key: str) -> dict | None:
    r = redis.Redis(connection_pool=_pool)
    val = await r.get(key)
    return json.loads(val) if val else None


async def set_cache(key: str, value: dict, ttl: int = 86400):
    r = redis.Redis(connection_pool=_pool)
    await r.setex(key, ttl, json.dumps(value, ensure_ascii=False, default=str))


def make_cache_key(user_query: str, top_n: int, city_override: str = None) -> str:
    raw = f"{user_query}|{top_n}|{city_override or ''}"
    return f"recommend:{hashlib.md5(raw.encode()).hexdigest()}"
```

### 3.4 限流中间件

```python
# app/middleware/rate_limit.py（新增）
"""三级限流：全局 + IP + 用户"""

import time
import redis.asyncio as redis
from fastapi import Request, HTTPException
from starlette.middleware.base import BaseHTTPMiddleware


class RateLimitMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request: Request, call_next):
        # 跳过非业务路径
        if not request.url.path.startswith("/v1/ai/"):
            return await call_next(request)

        user_id = request.headers.get("x-user-id", "anon")
        ip = request.client.host
        now = int(time.time())

        r = redis.Redis(connection_pool=_pool)
        # 三级检查
        for key, limit, window in [
            (f"rl:global:{now // 60}", settings.rl_global_per_min, 60),
            (f"rl:ip:{ip}:{now // 60}", settings.rl_ip_per_min, 60),
            (f"rl:user:{user_id}:{now // 60}", settings.rl_user_per_min, 60),
        ]:
            cnt = await r.incr(key)
            await r.expire(key, window)
            if cnt > limit:
                raise HTTPException(429, f"请求过频：{key.split(':')[0]}")

        return await call_next(request)
```

### 3.5 LLM 熔断器

```python
# app/clients/circuit_breaker.py（新增）
"""简单熔断器：连续 N 次失败 → 开路 → 一段时间后半开试探"""

import time
from enum import Enum
from typing import Callable, Awaitable


class CircuitState(Enum):
    CLOSED = "closed"  # 正常
    OPEN = "open"  # 熔断
    HALF_OPEN = "half_open"  # 半开试探


class CircuitBreaker:
    def __init__(self, fail_threshold=5, reset_timeout=60):
        self.fail_count = 0
        self.state = CircuitState.CLOSED
        self.last_fail_time = 0
        self.fail_threshold = fail_threshold
        self.reset_timeout = reset_timeout

    async def call(self, fn: Callable[..., Awaitable], *args, **kwargs):
        if self.state == CircuitState.OPEN:
            if time.time() - self.last_fail_time > self.reset_timeout:
                self.state = CircuitState.HALF_OPEN
            else:
                raise RuntimeError("CircuitBreaker OPEN")

        try:
            result = await fn(*args, **kwargs)
            if self.state == CircuitState.HALF_OPEN:
                self.state = CircuitState.CLOSED
                self.fail_count = 0
            return result
        except Exception as exc:
            self.fail_count += 1
            self.last_fail_time = time.time()
            if self.fail_count >= self.fail_threshold:
                self.state = CircuitState.OPEN
            raise


llm_breaker = CircuitBreaker(fail_threshold=5, reset_timeout=60)
```

```python
# app/middleware/token_budget.py（新增）
"""Token 预算控制：单用户单次/单日/全局单日三级"""

import tiktoken
import redis.asyncio as redis

_encoder = tiktoken.get_encoding("cl100k_base")


async def count_tokens(text: str) -> int:
    return len(_encoder.encode(text))


async def check_budget(user_id: str, input_tokens: int, r: redis.Redis) -> None:
    # 单次请求上限
    if input_tokens > settings.token_per_request_limit:
        raise HTTPException(400, f"输入超长：{input_tokens}>{settings.token_per_request_limit}")

    # 单用户单日
    daily_key = f"tok:user:{user_id}:{time.strftime('%Y%m%d')}"
    used = await r.incrby(daily_key, 0)
    if used > settings.token_user_daily_limit:
        raise HTTPException(429, "单日 token 预算耗尽")
    # 全局单日
    global_key = f"tok:global:{time.strftime('%Y%m%d')}"
    used_g = await r.incrby(global_key, 0)
    if used_g > settings.token_global_daily_limit:
        raise HTTPException(503, "全局 token 预算耗尽，已切换 mock 模式")
```

```python
# app/core/logging.py（新增）
"""结构化 JSON 日志 + request_id 贯穿"""

import logging
import json
import sys
import uuid


class JsonFormatter(logging.Formatter):
    def format(self, record):
        log = {
            "ts": self.formatTime(record),
            "level": record.levelname,
            "logger": record.name,
            "msg": record.getMessage(),
            "request_id": getattr(record, "request_id", "-"),
            "user_id": getattr(record, "user_id", "-"),
        }
        if record.exc_info:
            log["exc"] = self.formatException(record.exc_info)
        return json.dumps(log, ensure_ascii=False)


# main.py 初始化
handler = logging.StreamHandler(sys.stdout)
handler.setFormatter(JsonFormatter())
logging.basicConfig(level=logging.INFO, handlers=[handler])


# 中间件注入 request_id
class RequestIdMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request, call_next):
        request_id = request.headers.get("x-request-id", str(uuid.uuid4()))
        request.state.request_id = request_id
        # 用 contextvar 让所有日志自动带 request_id
        _request_id_ctx.set(request_id)
        response = await call_next(request)
        response.headers["x-request-id"] = request_id
        return response
```

```python
# app/main.py lifespan 改造
from signal import SIGTERM, SIGINT


@asynccontextmanager
async def lifespan(app: FastAPI):
    # 启动
    logger.info("启动...")
    # 预构建索引
    if settings.hybrid_retrieval_enabled:
        asyncio.create_task(_build_indices_async())

    stop_event = asyncio.Event()

    def _signal_handler():
        stop_event.set()

    loop = asyncio.get_event_loop()
    for sig in (SIGTERM, SIGINT):
        loop.add_signal_handler(sig, _signal_handler)

    yield

    # 优雅停机
    logger.info("收到停止信号，等待在飞请求...")
    # uvicorn --timeout-graceful-shutdown=30 已处理 worker 层
    # 这里只清理应用层资源
    await _close_async_engine()
    await _close_redis_pool()
    logger.info("停止完成")
```

## 7. 关键设计决策回顾

| 决策点 | 选择 | 理由 |
|---|---|---|
| 异步化范围 | 全链路 | I/O 密集型场景异步收益最大 |
| 限流维度 | 全局+IP+用户三级 | 防恶意刷 + 公平分配 |
| 熔断策略 | 失败计数 + 半开试探 | 业界标准做法 |
| 缓存粒度 | 按 query hash | 相同 query 命中率高 |
| API 版本 | /v1 前缀 | 破坏性变更有退路 |
| 健康探针 | liveness + readiness 分离 | K8s 滚动更新必备 |
| 部署副本数 | 2 | 起步，按 QPS 扩 |
| 容器用户 | 非 root | 安全合规 |

## 9. 学习要点小结

1. **异步化是商业化第一步**：I/O 密集型场景异步收益最大
2. **限流 / 熔断 / 降级是三个不同概念**：限流挡入口、熔断快速失败、降级返回兜底
3. **Token 必须有预算**：LLM 成本是变量，没有预算等于敞口袋烧钱
4. **API 加版本前缀**：商业客户最怕"接口突然变了"
5. **健康探针 liveness / readiness 必须分离**：K8s 滚动更新必备
6. **非 root 容器**：安全合规硬指标
7. **优雅停机**：SIGTERM → 拒新请求 → 等在飞 → 退出，避免丢请求
